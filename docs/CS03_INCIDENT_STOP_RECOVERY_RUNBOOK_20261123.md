# CS-03 障害時の安全停止・復旧手順（運用案／実環境未受入）
更新日: 2026-11-23
判定: **NO-GO**。この手順の作成は公開・隔離配置・課金変更の承認ではない。

## 対象と前提
対象はデータベーススペシャリスト学習アプリのCS-03アカウント連携（GitHub Pages → Cloudflare Worker → SQLite Durable Object → 隔離Neon Function → 隔離Neon PostgreSQL）。
**現状**：公開用 `cs03-config.js` の `previewEnabled:false`、隔離Neon Functions 0件、実クラウドWorker/DO未配置。障害復旧の実際のクラウド操作はまだ試せない。既存の端末内学習機能はCS-03と独立し、変更しない。

## 0. 絶対に守る境界
- GitHub `main`、既存サービス（特にParkWait等）のWorker/DO、production Neon DBには変更を加えない。
- 無承認でWorkers route／Function／DOを作成・公開・切替・削除しない。Free→有料・従量課金契約も禁止。
- 秘密、JWT、DB URL、メール、個人別の学習内容をissue/console/ログ/スクリーンショットへ出さない。
- Workerだけを止めてもFunction直アクセスを安全に遮断できたとは限らない。独立した `x-secret` + JWT + 本人RLSが維持されていることを確認する。
- 切戻しは**保存したデータの削除やDBのリセットを意味しない**。未保存下書きは自動廃棄しない。

## 1. 発生時の最初の判断
| 観測（例） | 基本判断 | 対応優先度 |
|---|---|---|
| 401 / 403 | 認証期限／不正Origin／秘密不一致を疑う。全件を障害と決めつけず、匿名化した集計で範囲確認 | 高 |
| 409 | 更新番号の競合。自動再送・上書きを止め、確認待ちデータを保持 | 高 |
| 429 | アカウント全体またはIP／ユーザー別上限。制限を緩めず、既存アプリ全体の消費を確認 | 高 |
| 503、DO応答失敗、Function接続不可 | **安全側で送信停止**。端末に残った未保存記録を保全 | 緊急 |
| Worker Free上限超過／route fail-open疑い | **公開を開始・継続しない**。Function直接アクセス拒否を別途確認 | 緊急 |
| 秘密漏えい／他人の記録を閲覧できる疑い | 直ちにCS-03の公開導線を停止する判断。後述の機密・権利事故対応へ | 最優先 |
| 端末内保存領域の異常／破損 | 読込・書込を停止。原本削除をせず、復旧手順を検討 | 高 |

**単発のネットワーク不調**を理由に記録削除、アクセス上限の解除、署名検証の無効化、JWTのログ出力はしない。

## 2. 即時の安全停止（現状と将来を分ける）
### 現状：未公開・未配置
1. `cs03-config.js` の `previewEnabled:false`、`authUrl:''`、`apiUrl:''` を読み取り確認。**この状態を維持する**。
2. `node scripts/cs03-predeploy-guard.mjs --report` を読み取り専用で実行し、`CS03_DEPLOY_READINESS=BLOCKED` と受入・承認の未達を確認。コマンドは配置を実行しない。
3. 隔離Neon Branch `br-snowy-truth-a162pmdt` のFunction一覧、CloudflareにCS-03の公開用Worker routeがないことを**読み取りで確認**。設定変更しない。
4. 何らかのテスト用データがある場合、DB上の行や他アカウントの記録を削除しない。事故証跡に秘密・本文を含めず、発生時刻・状態・分類だけを保存。

### 将来：個別承認済みの隔離環境のみ
1. 監督者の事前承認済み手順に従い、CS-03公開導線を**OFF**とする（元からOFFなら変更不要）。端末内学習を維持。
2. CS-03専用のWorker route／Functionへの**新規トラフィック遮断**を計画。CloudflareのFree超過時に**fail-open**を選ばない。各サービスの設定変更は権限・影響評価・明示承認後のみ。
3. Workerを停止するだけでなく、Neon Functionで **秘密不一致の要求が401で拒否される**／正しい署名なしでは実データを返さないことを別途確認。公開URLを直接公開して実験しない。
4. CS-03専用の処理停止だけを対象とし、共有Cloudflareアカウントの他Workerやproduction DBには触れない。
5. 接続元が不明・被害範囲不明なら**再開しない**。

## 3. 学習データの保全
1. CS-03アカウントモードで未保存記録がある場合は、ページ再読み込み・ログアウト・削除を避ける。通信失敗後は確認待ち記録のJSONバックアップを明示操作で出力し、管理できる場所に保管。
2. `src/cs03-draft-store.mjs` のアカウント別localStorageチェックポイントは再読み込み後に確認待ちで復元するが、暗号化・永続保存・別端末同期を保証しない。ブラウザの保存データを消さない。
3. 復元された記録は自動送信しない。アカウント一致とサーバー現行リビジョンの照合なしに、古い記録を上書きしない。
4. `discardPending` は確認待ちデータの**端末内だけの破棄**。データが必要なら操作しない。JSON原本があることを操作者が確かめる。
5. DBをバックアップから復元する判断はこの手順の対象外。独立の承認と整合性確認を必要とする。

## 4. 原因調査（秘密を出さずに実施）
記録する項目は、JST/UTC時刻、影響の範囲（CS-03だけか）、HTTP状態コードの件数、どの段階（Browser／Worker／DO／Function／DB）か、直前の承認済み変更、プランと残枠の読み取り結果、操作担当者・判断のみ。
- 401/403：Originの固定値とJWT issuer/audience/JWKS、Worker `CS03_GATEWAY_SECRET` とFunction `CS03_ORIGIN_SECRET` の**名称と設定有無**を確認。値の表示・コピー・貼付け禁止。
- 429：Worker／DO／Neonそれぞれの上限とアカウント合算使用量を確認。制限の無効化は禁止。
- 503：DOが利用不能でもインプロセス上限だけで透過させない、未承認モードでもリクエストを転送しないことを確認。
- 409：競合した端末記録は保持し、旧revisionによる再送をしない。
- 秘密漏えい疑い：証拠の閲覧範囲を制限し、認証情報の無効化・ローテーションは**CS-03専用の対象と影響を特定し承認した後**に実施。事故報告・個人情報保護上の判断は別に行う。

## 5. 切戻し・復旧の判断
- **切戻しの第一候補**：CS-03の公開導線OFFを維持し、従来の端末内学習だけを残す。アカウント履歴は復旧まで閲覧・更新を保留。
- 保存済みのサーバー記録は削除しない。原本保持と監査記録を優先する。
- 再開に必要な証拠：本人認証、JWT検証、固定Origin、秘密照合、本人RLS、直接Function URL拒否、共有DOの全体/IP/ユーザー別原子的レート制限、429/503 fail-closed、ブラウザの未保存復元、実Cloudflareルートの超過時fail-closed、アカウント全体Free枠・料金条件、CSP/CORS、独立した配置承認。
- これらが**全件合格**するまで CS-03はNO-GO。復旧のために保護を緩めてGOにしない。

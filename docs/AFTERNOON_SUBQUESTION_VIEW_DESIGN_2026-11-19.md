# 午後試験：設問ごとの問題文・図・回答（2026-11-19 合意事項）

## 決定仕様
- 午後Ⅰ・午後Ⅱの問題に適用する。午前の画面は変更しない。
- **大問→設問→小問**があれば階層を表示し、回答単位は原本の解答欄に対応する最小単位（例：設問1(1)、設問1(2)）。
- 午後の設問表示は**上下2段**。上段「問題文表示部」（共通の導入・注意事項と選択中の設問・小問文）。下段「図・表表示部」（その設問を解くために必要な資料のみ）。
- 共通導入・図表は設問切替時にも必要な場合表示する。設問が参照する図表をIDで明示的に関連づける。ひとつの図を複数設問から参照可。設問と無関係な図表は表示しない。
- **出題原本との忠実性が最優先**。推測した図・表・SQL・数値・人物名は表示しない。原本PDF照合済みの資料だけ追加する。確認できない図は「該当図は準備中。下の公式原本で確認してください。」と表示し、虚偽の図を作らない。
- 原本画像ページの閲覧部（前後ページ、拡大）、公式問題PDFリンク、公式解答・採点講評PDFリンクは**現行位置と動作を維持**。新たな図・表表示部はこれらとは別。
- **設問単位の記述回答**を独立して端末内保存し、設問切替・ページ再読込で復元する。既存の大問単位`written`や理解度を一切消さず、互換のまま残す。
- 公式解答は設問に対応する内容を正確に抽出できるものだけ設問別表示。未整備なら公式解答PDFへ誘導し、架空の正解を提示しない。
- 端末横幅が狭くても問題文→資料→記述欄の順で見えること。読めないサイズで図を縮小し過ぎず画像拡大を用意する。

## データモデル案
```js
{
  key: '2025:pm1:1',
  intro: '原本照合済みの大問導入文',
  materials: {
    figure1: {kind:'image',source:'verified-local-file',alt:'原本に即した図の説明'},
    table1: {kind:'table',columns:[/* verified */],rows:[/* verified */]}
  },
  subquestions: [
    {id:'s1-1',label:'設問1(1)',text:'原本照合済みの設問文',materialIds:['figure1']},
    {id:'s1-2',label:'設問1(2)',text:'原本照合済みの設問文',materialIds:['table1']}
  ]
}
```
画像は公式原本の適切な範囲を正確に切り抜いた画像または照合済み構造化表示に限る。図参照のない設問では誤って図を表示しない。

## 回答保存（互換）
- 既存`db-study-progress-v1`の`2025:pm1:1`など各大問記録は維持。
- 新規フィールド案：`writtenBySubquestion: { 's1-1': '...', 's1-2': '...' }`。既存`written`は読み取り・残存を維持し、ユーザーが明示的に移行を選ぶまで自動分解・削除しない。
- 「答えを見る」「理解度」「バックアップ／復元」でこのフィールドが失われないことを確認。既存のバックアップ形式に内包されることを確認。
- 文字入力時に設問IDから保存先を選び、全体`written`を上書きしない。

## 必須受入条件
1. 大問ごとに原本と一致する設問・小問一覧が出て、選択単位が一致する。
2. 設問(1)を表示すると設問(1)の問題文と必要資料だけが上下表示される。設問(2)への切替で文・資料・回答が正しく切り替わる。
3. 共通説明が必要な場合は必ず読める。設問切替で参照必須の情報が消えない。
4. 大問1の設問(1)と(2)に別々の解答を入力し、双方保存・再読込で復元できる。
5. 旧`written`、学習履歴、午前試験、原本画像ビューアに悪影響がない。
6. 原本未照合の設問・資料は未整備であることを明示し、原本表示へ安全にフォールバック。
7. PC/スマホの両方で表示確認し、CSPとブラウザエラーなし。

## 現状と手順
現在の午後問題は大問単位で、`questionData()`には午後の設問テキストが未登録。`#written`は`r.written`に大問単位で保存。`#localViewer`が原本画像を表示している。まだこの新仕様が実装されたわけではない。

1. まず対象年度・午後Ⅰ/午後Ⅱの公式原本にある設問番号・設問文・資料の対応を整理する（原本PDFとの照合）。
2. 既存の大問表示・回答保存を壊さず、小問セレクタと上下2段表示、独立記述欄を追加する。
3. 正確に照合できた問題だけ段階的に有効化。未整備問題は現行の原本ページ・大問単位の回答を引き続き使用できるようにする。
4. 本番mainへの変更、GitHub Actions、開発PCを必要とする操作はユーザーの許可なしに行わない。

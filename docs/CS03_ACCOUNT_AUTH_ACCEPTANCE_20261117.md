# CS-03 ユーザーアカウント・認証受入仕様（2026-11-17）

## 承認済みの要件
- メールアドレス＋パスワードで登録・ログイン。Neon Auth（Better Auth）を採用する方針。
- 新規登録、メール確認、ログイン、ログアウト、パスワード再設定、アカウント削除を対象とする。
- ユーザーID単位で学習履歴を保存し、同じアカウントでPC・スマホ間同期。
- 未ログイン時は従来の端末内学習を継続できる。JSONバックアップ／復元は残す。
- 初回ログインで既存履歴があれば、バックアップと本人による明示選択なしにアップロード・上書きしない。
- アカウント切替時、前ユーザーの端末内履歴を別ユーザーに表示・送信しない。

## 画面と処理の設計
1. 未ログイン：登録・ログイン入口と「この端末のみ保存」を表示。
2. 登録：メールアドレス、パスワード、確認用パスワードを入力。登録API成功後はメール確認待ちとする。アカウント存在有無の漏えいを抑制。
3. メール確認：Neon Authの実API・メール送信仕様を検証後に実装。未確認を確認済み扱いしない。
4. ログイン：認証済みセッションから本人IDを確定。端末履歴がある場合は移行確認を出し、勝手に同期しない。
5. 同期：本人の行のみ読み書き。通信失敗時も端末内の履歴を残す。
6. ログアウト・ユーザー切替：セッションを破棄し、他ユーザーの履歴を表示・送信しない。共有端末上のデータ保持／消去は明示選択。
7. パスワード再設定：メールで本人確認し、既存セッションの失効を検証。
8. アカウント削除：本人再認証・明示確認・学習履歴を含む削除範囲の検証後に公開。

## セキュリティ条件
- パスワード平文・DBパスワード・秘密API鍵・特権トークンを公開HTMLやlocalStorageに保存しない。
- RLSの本人判定は検証済みJWT／認証情報から取得する。クライアント指定user_idは信用しない。
- 本人のみSELECT/INSERT/UPDATE可、他人・匿名は拒否。UPDATEはUSINGとWITH CHECKの両方を検証。
- 削除処理・競合解決・2端末同期・メール送信の実動作は隔離環境で確認する。
